# my-gacha 설계 문서 (초안 v0.1)

AI가 세계관과 캐릭터를 만들어 주는 개인용 가챠 게임.
나와 친구들이 각자 자기 API 키로, 각자 자기 브라우저에서 노는 용도. 상업적 용도 없음.

참고한 것: Marinara Engine의 Gacha Forge (구조와 아이디어만 참고, 코드·프롬프트·그림은 가져오지 않음).

---

## 0. 원칙

1. **서버 없음.** Cloudflare Pages(무료, `my-gacha.pages.dev`)에 올린 정적 웹앱. 모든 계산과 저장은 각자 브라우저 안에서.
2. **모바일 우선 + 넓은 화면은 넓게.** 폰 세로 화면을 먼저 설계하고, PC에서는 넓은 화면을 다 쓰는 배치로 바꿔 보여 줌(아래 7-1).
3. **LLM은 콘텐츠만 만든다.** 뽑기, 확률, 재화, 전투 결과는 전부 코드로 계산. AI에게 "뽑기 결과"를 묻지 않음.
4. **월드와 진행을 나눈다.** 월드(만든 것)는 공유할 수 있고, 진행(내 뽑기·재화·보유 캐릭터)은 내 것.
5. **API 키는 브라우저 밖으로 안 나간다.** 월드 팩, 세이브 백업 어디에도 키를 넣지 않음.
6. **한 번에 다 만들지 않는다.** 단계(Phase)별로 "놀 수 있는 상태"를 하나씩 완성.

## 1. 전체 구조

```
[브라우저 (PWA, 홈 화면에 설치 가능)]
 ├─ UI (화면)
 ├─ 게임 코어 ── 순수 함수, 시드 고정 난수
 │    가챠 / 재화 / (나중에) 전투 / 성장
 ├─ 생성기 ──── 프롬프트 만들기 → 호출 → JSON 검증 → 실패 시 재시도
 │    ├─ 텍스트 어댑터: OpenAI 호환(OpenRouter, OpenAI, NanoGPT), Claude, Gemini
 │    ├─ 그림 어댑터: NovelAI, PixAI
 │    └─ 작업 큐: 연결마다 동시 1개, 내가 기다리는 작업이 먼저
 ├─ 저장소 ──── IndexedDB (Dexie)
 └─ 팩 입출력 ── 월드 팩 / 세이브 백업 (.zip)

(필요할 때만) Pages Functions 중계기 ── 브라우저 직접 호출이 막힌 API용 (같은 사이트 안 /api/relay)
```

게임 코어는 화면, 저장소, 생성기를 몰라야 한다. 입력을 받아 결과만 돌려주는 함수로 만들어서 테스트를 쉽게 한다.

## 2. 데이터 모델

### 2-1. 월드 쪽 (공유 가능, 월드 팩에 들어감)

| 이름 | 내용 |
|---|---|
| **World** | id, 이름, 언어, 세계관 설명, 시나리오, 작가 지시문, 화풍 설정(그림 공통 태그), 속성 목록, 태그 목록, 재화 이름, 스키마 버전 |
| **Character** | id, 이름, 희귀도(3~6★), 태그, 외형 설명(글), 그림용 태그(영어, 한 번 만들어 고정), 성격, 배경 이야기, 대사 몇 줄, 초상화 이미지 id, (나중에) 전투 능력치·스킬 |
| **Banner** | id, 종류(상시/한정), 이름, 기간(선택), 픽업 캐릭터 목록, 배너 그림 id |
| **Story** (선택) | 챕터, 노드, 대사. 월드 팩에 넣을지는 내보낼 때 고름 |
| **Asset** | 이미지 Blob(WebP로 줄여 저장), 원래 프롬프트, 시드 |

### 2-2. 진행 쪽 (나만의 것, 세이브 백업에만 들어감)

| 이름 | 내용 |
|---|---|
| **Save** | 어느 World의 진행인지, 재화, 보유 캐릭터(캐릭터 id + 잠재 단계), 배너별 천장 카운터, 배너별 첫 10회 보장 여부, 300회 교환 포인트, 뽑기 기록, 스토리 진행 위치 |
| **Settings** | 연결 프로필(서비스, 주소, **API 키**, 모델), 작업별 연결 지정, 화면 설정 |

한 World에 Save가 여러 개 있어도 되게 한다. 같은 월드를 처음부터 다시 하기 쉽게.

### 2-3. 설계상 중요한 결정

- **스토리 등장인물은 "월드 캐스트"에서 고른다. "내가 뽑은 캐릭터"에서 고르지 않는다.**
  그래야 친구에게 스토리를 넘겨도 친구 진행과 충돌하지 않는다.
  (Gacha Forge는 보유 캐릭터 기준이었는데, 우리는 공유가 목적이라 반대로 감.)
- 모든 데이터에 `schemaVersion`을 넣는다. 나중에 구조가 바뀌어도 옛날 월드 팩을 읽을 수 있게.

## 3. 가챠 규칙 (명일방주 기준)

※ 수치는 구현 전에 한 번 더 확인할 것. 전부 월드 설정에서 바꿀 수 있게 상수로 둔다.

| 항목 | 값 |
|---|---|
| 기본 확률 | 6★ 2% / 5★ 8% / 4★ 50% / 3★ 40% |
| 6★ 천장 | 50회 연속 6★ 없음 → 51회차부터 매 회 +2%p. 6★가 나오면 0으로 초기화 |
| 천장 카운터 | 상시 배너끼리 공유, 한정 배너는 배너마다 따로 |
| 첫 10회 보장 | 배너마다 첫 10회 안에 5★ 이상 1회 |
| 픽업 | 6★가 나왔을 때 픽업일 확률: 상시 50%, 한정 70%. 5★도 같은 방식 |
| 300회 교환 | 한정 배너에서 1회 뽑을 때마다 1포인트, 300포인트로 픽업 캐릭터 교환 |
| 중복 | 잠재 +1 (최대 6). 그 이상은 상점 재화로 전환. 화면에서는 "공명"으로 부르고 공명 0~5로 보여 준다 (src/ui/terms.ts) |

구현 메모:
- 확률 계산은 `pull(state, banner, rng) → { result, newState }` 같은 순수 함수.
- 난수는 시드 고정 RNG. 같은 시드면 같은 결과가 나와서 테스트와 버그 재현이 쉬움.
- 10연차는 1회차를 10번 순서대로 돌린다(천장 계산이 섞이지 않게).
- 확률 시뮬레이션 테스트: 10만 회 돌려서 실제 비율과 천장 동작을 확인.

### 재화 (1단계는 단순하게)

- 뽑기 재화 1종(이름은 월드가 정함, 예: "성석"), 상점 재화 1종(중복으로 얻음).
- 얻는 곳: 월드 시작 선물, 매일 접속 보상, 스토리 클리어.
- **친구끼리 노는 용도라서, 설정에서 재화를 마음대로 채우는 "자유 모드" 스위치를 둔다.**

### 공통 태그

- 고정 목록에서만 고름. 분류: 위치(근거리/원거리), 역할(딜러, 방어형, 치료, 지원, 군중제어, 소환 …), 속성(월드가 정함), 특징(신입/베테랑/엘리트, 희귀도 연동).
- 태그 목록은 월드 설정에서 바꿀 수 있음.
- 1단계 용도: 필터와 표시. 나중에 공개모집과 편성 시너지에 재사용.

## 4. 생성 파이프라인

### 4-1. 연결

- **연결 프로필**: 서비스 종류, 주소, API 키, 모델 이름. 여러 개 만들 수 있음.
- **작업별 연결 지정**:
  - 구조화 작업(캐릭터 시트, 계획 등 JSON) → 똑똑한 모델
  - 문장 작업(스토리 대사) → 더 싼 모델로 따로 지정 가능
  - 그림 → NovelAI 또는 PixAI
- 지정한 연결이 실패하면 기본 연결로 한 번 더 시도.

### 4-2. 텍스트 생성 규칙

- 결과는 항상 JSON으로 받는다. 받은 뒤 스키마 검사(zod).
- 실패하면 "무엇이 틀렸는지"를 붙여서 재시도(최대 2~3번).
- 너무 엄격하게 보지 않는다. 대소문자, 동의어 같은 사소한 차이는 받아 주고 정규화.
  (Gacha Forge도 이걸 고쳐서 여러 모델에서 성공률이 크게 올라감.)
- 생각하는 모델(reasoning)은 출력 토큰이 모자라 끊기는 일이 많으니 여유 있게 잡는다.
- 토큰 사용량을 기록해서 설정 화면에서 볼 수 있게.

### 4-3. 그림 생성 규칙

- 캐릭터를 처음 만들 때 외형 설명(글)에서 **그림용 태그를 한 번만 뽑아 저장**한다. 이후 모든 그림은 이 태그를 씀 → 같은 캐릭터가 매번 다르게 그려지는 걸 줄임.
- 그림 프롬프트는 항상 영어 태그. 월드 언어가 한국어여도 마찬가지.
- 월드 공통 화풍 태그 + 캐릭터 태그 + 상황 태그 순서로 조립.
- 같은 그림을 두 번 그리지 않게, 그리기 직전에 "이미 있나?"를 다시 확인.
- 저장 전에 WebP로 줄인다(폰 저장 공간).

### 4-4. 작업 큐

- 연결마다 한 번에 하나씩만 보낸다(요청 제한, 비용 폭주 방지).
- 사용자가 화면에서 기다리는 작업이 먼저, 미리 그려 두기 같은 백그라운드 작업은 뒤로.
- 앱을 닫거나 폰 화면이 꺼지면 멈춘다 → 다시 열면 남은 작업을 이어서.

## 5. 저장과 공유

### 5-1. 브라우저 저장 (IndexedDB)

- 저장 공간 유지 요청(`navigator.storage.persist()`).
- iPhone Safari는 오래 안 쓰면 데이터를 지울 수 있다 → "홈 화면에 추가" 안내 + 백업 알림(예: 일주일마다).

### 5-2. 월드 팩 (.zip)

```
my-world.gachapack.zip
 ├─ manifest.json    형식 버전, 월드 이름, 만든 사람(선택), 만든 날짜, 들어 있는 것 목록
 ├─ world.json
 ├─ characters/*.json
 ├─ banners/*.json
 ├─ images/*.webp
 └─ story/           (내보낼 때 "스토리 포함"을 체크했을 때만)
```

- 가져오기: 새 월드로 추가 + 빈 Save 하나 생성.
- 가져올 때 형식 버전을 확인하고, 옛날 형식이면 변환.
- API 키, 내 진행, 뽑기 기록은 절대 안 들어감.

### 5-3. 세이브 백업 (.zip)

- 월드 + 내 진행 전부. PC와 폰 사이에 옮길 때, 그리고 백업용.

## 6. CORS와 중계기

- OpenRouter, OpenAI, Gemini, Claude는 브라우저에서 직접 호출 가능한 것으로 알려져 있음.
- NovelAI, PixAI, NanoGPT는 **확인 필요** → 0단계에서 테스트 페이지로 확인.
- 막혀 있으면 같은 Cloudflare Pages 사이트에 Pages Functions 중계기(`/api/relay`, 무료 하루 10만 요청)를 둔다.
  - 같은 사이트 주소에서 온 요청만, 허용된 API 주소로만 전달.
  - 키는 저장하지 않고 통과만.
  - 막힌 서비스만 자동으로 중계기를 거치게(서비스별 설정으로 끄고 켤 수 있음).

## 7. 화면 목록 (1단계)

1. **처음 화면**: 월드 목록, 새 월드 만들기, 월드 팩 가져오기
2. **연결 설정**: 프로필 추가, 연결 테스트, 작업별 지정
3. **월드 만들기 마법사**: 세계관 입력 → 설정(언어, 화풍, 속성, 재화 이름) → 캐스트 생성 → 확인·수정 → 그림 생성
4. **홈**: 대표 캐릭터, 재화, 메뉴
5. **뽑기**: 배너 선택, 1회/10회, 천장 카운터 표시
6. **뽑기 연출과 결과**
7. **캐릭터 목록**: 태그·희귀도 필터, 보유 여부
8. **캐릭터 상세**: 초상화, 프로필, 대사, 잠재 단계, 초상화 다시 그리기
9. **뽑기 기록**
10. **월드 설정**: 확률 수치, 자유 모드, 내보내기

### 7-1. 화면 크기별 배치

| 폭 | 배치 |
|---|---|
| 폰 (~600px) | 한 열. 아래쪽 탭 메뉴. 상세 화면은 새 화면으로 넘어감 |
| 태블릿 (600~1100px) | 두 열. 목록 + 상세를 나란히 |
| PC (1100px~) | 왼쪽 메뉴 고정 + 넓은 본문. 캐릭터 목록은 여러 열 격자, 목록·상세·편집을 한 화면에. 10연차 결과는 가로 한 줄(5×2) |

- 화면마다 "폰 배치"와 "넓은 배치"를 따로 짜되, 데이터와 동작은 같은 컴포넌트를 씀.
- 홈 배경, 뽑기 연출, (나중에) 스토리 화면은 넓은 화면에서 가로 그림을 꽉 차게 씀.

## 10. 결정된 것

0. **3★·4★도 캐릭터 (안 A).** 시작 캐스트 6★ 2 / 5★ 3 / 4★ 4 / 3★ 4 = 13명. 6★·5★는 한 명씩 자세한 시트, 3★·4★는 한 번 호출에 여러 명을 묶어 짧은 시트로 생성. 새 배너가 열릴 때마다 6★ 1 + 5★ 1명 추가.
1. **그림은 처음 뽑았을 때 그린다.** 월드를 만들 때는 그림을 그리지 않음.
   - 그림 연결이 없어도 게임은 시작할 수 있다. 초상화는 빈 칸(실루엣)으로 두고, 그림 연결을 추가하면 그때 그린다.
   - 결과 화면에서는 실루엣 카드로 먼저 보여 주고, 그림은 뒤에서 하나씩 그림.
   - NovelAI 밴 방지: 그림 요청은 동시에 1개만, 요청 사이 최소 간격(설정, 기본 10초 이상), 자동 연속 생성 없음. 3★·4★는 자동으로 그리지 않고 "그리기" 버튼으로만 그리는 옵션.
2. **받은 월드도 마음대로 고칠 수 있다.** 가져온 월드는 내 월드와 똑같이 취급(캐릭터·배너 추가, 수정, 삭제 자유).
3. **2단계 전투는 턴제.** 다만 능력치에 사거리·저지 수 같은 값도 미리 넣어 두어, 나중에 디펜스 모드를 따로 붙일 여지를 남김.

## 11. 참고

### 참고: Gacha Forge의 방식 (번들 코드에서 확인)

- 시작 캐스트는 **5명뿐**: 5★ 2명 + 4★ 3명, 그리고 플레이어 본인(주인공).
- **3★ 결과는 캐릭터가 아님.** 재화(Glimmer) 1개가 나옴. 원래는 아무것도 안 줬다가("94%의 뽑기가 빈손") 나중에 재화를 주도록 고침.
- 4★·5★ 풀은 **무기**로 채움. 4★ 무기는 능력치만 있는 "흔한 것"이라 한 번 호출로 여러 개를 한꺼번에 생성.
- 14일마다 픽업 배너가 바뀌면서 **새 캐릭터 2명**이 추가됨. 캐스트는 시간이 지나며 늘어남.
